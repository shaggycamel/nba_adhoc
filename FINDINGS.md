# Predicting next-game player usage: what worked

Target: `usg_pct` for a player's next game, using only information available
before tip-off. Evaluation is on expanding-window season folds — train on
every earlier season, score the next one — with no shuffling anywhere, and
every feature computed from games strictly before the one being predicted.

Numbers below are regenerated by `nba_usage.run_final` (`RESULTS.md`) and
`nba_usage.run_processing` (`RESULTS_processing.md`).

## Headline

| | 2024-25 | 2025-26 |
| --- | --- | --- |
| Best baseline (EWMA, half-life 3) | 0.05173 MAE, R² 0.294 | 0.05099 MAE, R² 0.318 |
| **Best model (Ridge / ElasticNet)** | **0.04945 MAE, R² 0.356** | **0.04886 MAE, R² 0.372** |

The winning combination is a **regularised linear model on lagged usage
history plus injury-absence and rotation-position features**. It beats the
best baseline by about 4% on MAE and adds roughly 0.06 to R², consistently on
both folds.

That is a real gain but a modest one, and the honest summary of this project
is that **usage is mostly autocorrelated and only slightly contextual**. A
single feature — the EWMA of a player's recent usage — gets most of the way
there, and everything else is a small correction on top.

## Which variables drive usage

Ablation with Ridge, MAE:

| feature set | 2024-25 | 2025-26 |
| --- | --- | --- |
| history only | 0.05006 | 0.04951 |
| + injury absence | 0.04982 | 0.04917 |
| + rotation position | **0.04945** | **0.04888** |
| + pairwise absorption | 0.04943 | 0.04887 |
| + role clusters | 0.04945 | 0.04889 |

Greedy forward selection, validated on 2025-26, ranks the drivers:

1. `usg_pct_ewm10` — EWMA of recent usage (0.05007 on its own)
2. `expected_load_share` — share of the available rotation's usage-load (0.04949)
3. `min_r10` — rolling minutes (0.04916)
4. `usg_pct_season` — season-to-date usage (0.04911)

Three features recover about 87% of the gap between the best baseline and the
full 97-feature model; twelve recover 98% (0.04893 against 0.04888). **The
other 85 features are almost entirely redundant.** If this goes into
production, the small model is the one to ship.

## Injury: real, but not the key variable

The project brief expected injury to be a key variable. It is not. Tested as
its own ablation (Ridge, mean over folds):

| injury encoding | MAE |
| --- | --- |
| none | 0.04978 |
| **player's own report status only** | **0.04978** |
| count of teammates out | 0.04977 |
| vacated usage-load | 0.04969 |
| vacated share of team load | 0.04969 |
| all absence features | 0.04950 |
| all absence + rotation position | 0.04917 |

Two things stand out.

**The player's own injury status is worth nothing** — 0.04978 against 0.04978
for no injury features at all. On reflection this is what should happen: the
target only exists for games the player actually played, so conditioning on
having played already absorbs almost everything their status could tell us.
Own status would matter for predicting *whether* someone plays, which is a
different question from the one asked here.

**Teammate absence matters mainly through rotation position, not through
volume.** Knowing how much usage was vacated is worth ~0.0003 MAE; knowing
where the player now sits in the healthy rotation is worth another ~0.0003 on
top, the single largest structural contribution. What matters is not how much
load went missing but how far up the pecking order it pushes this player.

## What failed

**Role clustering** (k-means over prior-game rate stats with usage excluded,
refitted per season, plus role-aware vacated load) changed MAE by ≤0.00002 in
either direction. Per the project rule that clusters are kept only on a
demonstrated gain, it is excluded from the recommended set.

**Pairwise with/without absorption** — shrunk estimates of how each player's
usage shifts when each specific teammate is out — also added nothing
(0.04945 → 0.04943). The individual estimates look sensible (the strongest
pair is +7.7 usage points over 42 games-without), but by the time rotation
share is in the model the pairwise detail is redundant. Teammate-specific
synergy, as measured here, does not forecast usage.

**Neural networks lost to linear regression.** The MLP with player embeddings
(0.05035 / 0.04933) and the GRU over each player's last ten games
(0.05086 / 0.04957) were the two worst models tested — beaten by every
classical algorithm, though still ahead of the baselines. The sequence model
was worst of all, which says the ordering of recent games carries no signal
beyond their weighted average.

## Algorithm choice barely matters

On the same features and folds, 2025-26:

| model | MAE |
| --- | --- |
| ElasticNet | 0.04886 |
| Ridge | 0.04888 |
| CatBoost | 0.04892 |
| XGBoost | 0.04892 |
| Random forest | 0.04894 |
| LightGBM | 0.04900 |
| Extra trees | 0.04904 |
| MLP + embeddings | 0.04933 |
| GRU sequence | 0.04957 |

Every classical algorithm lands within 0.0002 MAE, and the two linear models
are at the top of both folds. There is no non-linear structure here worth
chasing: spend effort on features, not on model class.

## Processing choices

**Window length hardly matters.** Long windows (5/10/20/40) edge it at 0.04914
against 0.04931 for short ones (3/5) — a 0.0002 spread across every variant
tried. EWMA alone does as well as a full set of rolling windows. Short
windows are measurably the worst: a 3-game mean is too noisy, which also
shows in the baselines, where last-3 is the weakest of the lot.

**Most of the error lives in low-minute players.** Restricting to games of 10+
minutes lifts R² from 0.364 to 0.506. This is *not* an improvement — it is a
different, easier row set, and the MAEs are not comparable. But it locates the
problem: garbage-time and cameo appearances have erratic usage and are close
to unpredictable. A production model would likely be scoped to the rotation
rather than trained to chase them.

## Caveats

- **Injury data starts 2021-10-19**, so every injury-aware result uses five
  seasons, not the seventeen the box scores cover.
- **10,160 of 64,246 injury rows are dropped** because they do not match a game
  for that team on that date — the NBA publishes the report the evening
  before, so some rows carry the report date rather than the game date. This
  understates absences; it cannot leak. Recovering them would be the first
  thing to try if the absence features were worth pushing further.
- **Two folds only** for the injury-era results. The differences between the
  top models are smaller than the gap between folds, so treat the model
  ranking as "all equivalent" rather than "ElasticNet wins".
- Usage is modelled conditional on the player appearing. Predicting usage for
  a player who might be ruled out needs an availability model first.

# Predicting usage, minutes and volume

Targets: a player's `usg_pct` in their next game, the minutes they will
play, and the points, rebounds and assists that follow — using only what is
known before tip-off.

Evaluation throughout is on expanding-window season folds (train on every
earlier season, score the next), nothing shuffled, every feature computed
from games strictly before the one being predicted. All numbers are
regenerated by the scripts named at the end; none are transcribed by hand.

## The short version

**Minutes is the useful model, not usage.** On the case that motivated the
work — a backup filling in for an injured starter — modelling nearly doubles
the explained variance in minutes, while the usage model's edge over a
recent average is much smaller. If one thing ships, it is the minutes model.

| target, backup-stepping-up slice | recent average | model | R² gain |
| --- | --- | --- | --- |
| minutes (2024-25) | 5.857 MAE, R² 0.273 | **5.053, R² 0.479** | +0.21 |
| minutes (2025-26) | 5.901 MAE, R² 0.251 | **5.103, R² 0.466** | +0.22 |
| points (2025-26) | 4.025 MAE, R² 0.184 | **3.823, R² 0.295** | +0.11 |
| usage (2025-26) | 0.05099 MAE, R² 0.318 | **0.04886, R² 0.372** | +0.05 |

## Nine ideas tested, one replicated

| block | verdict | evidence |
| --- | --- | --- |
| Injury absence | **kept** | usage 0.05006 → 0.04982 MAE |
| Rotation position | **kept** | usage 0.04982 → 0.04945; largest structural effect |
| Standings and incentives | **kept** | best on both folds, both targets, both model families; also lifts the duration model's AUC on all three folds |
| Role clusters | rejected | ≤0.00002 MAE either way |
| Pairwise absorption | rejected | 0.04945 → 0.04943, noise |
| Component decomposition | rejected | 0.04888 → 0.05038, clearly worse |
| Absence duration | rejected | minutes 5.070 → 5.082 |
| Player biography | rejected | behind on 3 of 4 minutes cells |
| Opponent form / mismatch / churn | rejected | opposite directions on the two folds |

**The pattern is the finding.** Everything that failed was a re-expression
of information already in the player's own rolling history. The one block
that replicated describes something the player's record structurally cannot
contain: what the organisation wants. A team above the playoff line in March
behaves differently from one out of the race, and no amount of a player's
past box scores reveals that.

## Usage

Best model: Ridge or ElasticNet (they are indistinguishable) on 97 features
of lagged history plus absence and rotation. MAE 0.04945 and 0.04886 across
the two folds against 0.05173 and 0.05099 for the best baseline — about 4%.

Three results worth keeping:

**Usage is mostly autocorrelated.** An EWMA of recent usage is most of the
model. Three features recover 87% of the gap between baseline and the full
97; twelve recover 98%. The other 85 are redundant.

**A player's own injury status is worth nothing** — 0.04978 with it, 0.04978
without. The target only exists for games they played, so conditioning on
having played already absorbs it. It would matter for predicting *whether*
someone plays.

**Algorithm choice is irrelevant.** Seven classical algorithms land within
0.0002 MAE. The two neural networks — an MLP with player embeddings and a
GRU over recent games — were the *worst* fitted models, the sequence model
worst of all, which says the ordering of recent games carries nothing beyond
their weighted average.

## Minutes

LightGBM on the usage features plus the minutes-allocation terms and
standings. The allocation terms come from an identity: a team plays 240
minutes, so a player's share of the *available* rotation implies an
allocation directly, and it rises on its own as the rotation thins.

That structural term is worth noting on its own. `expected_min_share × 240`,
with no model fitted at all, reaches 5.611 MAE on the backup slice — already
better than both recent-average baselines (5.731 and 5.901).

## Volume

`stat = minutes × (stat per minute)`, each factor its own model, the rate
model also fed an out-of-fold usage prediction. It is level with predicting
the stat total directly, not ahead of it — the gain comes from the absence
and rotation features both share, not from the factorisation.

The usage identity explains why the decomposition disappoints. It rearranges
so the player's own minutes cancel: usage is the player's event rate divided
by the team's. Decomposing the numerator is then provably inert for a linear
model, since Ridge is linear in the target and three component fits recombine
to exactly the fit on their sum. What is left is the division, where the
ratio of two conditional means is a biased estimate of the mean of the ratio.

## Caveats

- **Injury data starts 2021-10-19**, so every injury-aware result uses five
  seasons, not the seventeen the box scores cover. Two validation folds.
- **10,160 of 64,246 injury rows are dropped** — the report is published the
  evening before, so some rows carry the report date rather than the game
  date. This understates absences; it cannot leak.
- **2021-22 is unusable for absence spells.** Its report matches too few
  games for consecutive absences to join up, so every spell reads as one
  game.
- **Minutes are whole numbers in this dataset**, and `usg_pct` is stored to
  three decimals. Reconstructing usage from its observed components misses
  the stored column by 0.0138 MAE — a floor on anything formula-based.
- **`player_info` covers only two seasons.** Static attributes are
  broadcast from the latest record, so players who left before 2024-25 have
  none.
- Differences between the top models are smaller than the gap between folds.
  Read model rankings as "equivalent" rather than as a winner.
- Everything is conditional on the player appearing. Projecting someone who
  might be ruled out needs an availability model first.

## What I would do next

Not more features. Nine blocks at this hit rate says the marginal return is
near zero, and the two that worked were found by looking outside the
player's own record rather than by deriving more structure from inside it.

The binding constraints are data, not method: minute-and-second resolution
(which the NBA publishes) would remove the reconstruction floor, and an
injury feed carrying expected return dates would let the duration model work
properly instead of inferring severity from body-part text.

| command | writes |
| --- | --- |
| `uv run python -m nba_usage.run_final` | `RESULTS.md` |
| `uv run python -m nba_usage.run_experiments` | `RESULTS_ablation.md` |
| `uv run python -m nba_usage.run_processing` | `RESULTS_processing.md` |
| `uv run python -m nba_usage.run_components` | `RESULTS_components.md` |
| `uv run python -m nba_usage.run_volume` | `RESULTS_volume.md` |
| `uv run python -m nba_usage.run_minutes` | `RESULTS_minutes.md` |
| `uv run python -m nba_usage.make_report` | `report.html` |

`nba_usage/recommended.py` holds the surviving configuration: which feature
blocks are in, which are excluded by name, and which model to fit per
target. Rejected blocks stay in the repository so their negative results
remain reproducible.
